## 1. Harness 到底迁移了什么

直接依赖包括 `@earendil-works/pi-ai@0.85.1`；目录同步脚本固定 Harness / pi-ai 版本与提交，已有许可证说明。当前固定的上游 [README](https://github.com/deepseek-ai/deepseek-harness/blob/0a15e36e7f82b6ed45af6fa9759f29b40dcd965d/README.md) 描述的是基于 Cordis 的插件体系，且仍处于 developer preview。SP 不是直接运行这一整套体系。

| 能力 | 当前判断 |
| --- | --- |
| 多模型桥接、模型目录、BYOK | 已有实现，目录检查通过；真实 provider 成功率待实测 |
| 模型自主调用领域工具 | 已有；问卷、媒体、项目、Skill、结果、发布等工具复用 SP 领域能力 |
| 多步执行、重试、停滞检测、上下文压缩 | 已有框架，不代表所有中断边界可靠 |
| 会话 / run / 工具事件与历史展示 | 已有，明显优于单次 HTTP 聊天 |
| Queue / checkpoint / 恢复 | 部分实现，缺少可靠的认领、去重、终态防重放和副作用恢复闭环 |
| steer / cancel / approval | 有入口和后端机制，但存在取消顺序问题，审批展示不充分 |
| 流式文字 | 不是 token 流式；前端实际反复请求完整 session，并未使用增量 cursor |
| 长对话记忆 | 当前实际跨 run 历史只取最近 12 条 UI 文本，工具历史和旧记忆没有完整接通 |
| 编辑器上下文与撤销 | 未闭环，是问卷产品体验的主要缺口 |
| Harness 桌面、shell、任意文件工具、插件生态 | 没有整套迁入；这些不是网页问卷产品的必需品 |

优先级应是“正确完成、可恢复、可撤销”，然后才是更细的流式动画。无需为了叫 Harness 而扩大执行权限。

## 2. 上线前必须处理的问题

### A. 保存核对会把未生效的修改判为成功【已复现】

位置：`worker-lib/agent/runtime/draftVerify.mjs:17-43,61-64`。

结构签名只比较 page.name 和 question.name:type。标题、选项、量表范围、必答条件、跳题、媒体文件夹和 trial 配置变化都可能被忽略。重试结束后，旧时间戳但相同结构也会返回 `structural-stale` 成功。

本地复现：期望标题更新且量表改成 7 分；读回仍为旧标题和 5 分，返回 `ok: true, reason: structural`。读回旧日期的同结构草稿，最终也可返回成功。

修复：以服务端规范化后的完整语义配置和提交 revision 核对；明确列出允许忽略的临时字段及默认值。不能用题目名称/类型代替内容一致性，也不能把旧 revision 降级成成功。读后延迟可以重试，超时应显示“保存已提交、核对未完成”，不得声称已核实。

### B. 恢复执行不能保证不重复副作用【代码路径 + 模拟复现】

位置：`designerChat.mjs:173-205,331-340,514-535`；`sessions.mjs:361-381`；`loop.mjs:115-147`；`runDispatcher.mjs`。

- Queue 消费者用 job 携带的 checkpoint 执行，未先从数据库读取当前权威 checkpoint / 终态。
- `markRunRunning` 更新 queued/running，但不检查是否实际更新到一行。终态任务仍可能继续执行。
- 正常 checkpoint 在一段步骤之后保存，不能覆盖“副作用完成、checkpoint 尚未落地”的崩溃窗口。
- 保存 continuation checkpoint 的异常被吞掉；发下一条队列消息与保存 checkpoint 不是同一可靠交接。
- `exclusive` 是单次工具循环内部的串行，不是跨消费者、跨标签页的锁。
- 已批准 pendingToolCall 在调用 `checkCancelled` 之前执行。

模拟工具复现：`checkCancelled` 始终为 true，恢复已批准操作后仍发生一次写入，然后才抛 CANCELLED；再次提供同一 checkpoint，会再写一次。该实验未连接真实数据库，证明的是恢复分支自身缺少取消前置及重复执行保护，不是声称生产已发生重复删除。

修复：run 认领 / 租约和版本校验；每次恢复读取 DB 权威状态；终态禁止重新执行；副作用调用具有稳定幂等标识与持久执行记录；审批与参数/目标/revision 绑定且不可重复消费；每次副作用前检查取消；明确 unknown outcome 的核对流程。平台支持幂等的操作复用幂等能力，否则必须核对实际结果，不承诺通用 exactly-once。checkpoint 与队列交接使用可恢复的投递记录或同等机制，不能吞写入失败。

### C. Silicon 没有遵循真人问卷的媒体和题目规则【部分已复现】

位置：`worker-lib/silicon/mediaAssign.mjs:26-49`；`answerValidate.mjs:1-50`；`handlers.mjs:183-184`；`runner.mjs:117-173,227-239`。

- 抽图只是对全池 URL 洗牌后取前 N 个；没有复用真人的文件夹、category/set、固定选图、mediaSlots、trial 分配规则。
- run 保存问卷和媒体列表，但未保存媒体 dataset 的文件夹/category 配置。
- 每道题只答一次；没有完整 trial 流程、条件分支、前序答案上下文。
- 提示词只提供题型/标题/choices 或 rateValues，未完整提供范围、矩阵维度等答题合同。
- 只把前 6 张图发给模型，`displayed_images` 却记录所有分配图片。
- 使用少量不支持类型的黑名单，其他未知类型默认支持。
- 数字只验证是否为有限数；选择/排序不验证选项成员、唯一性等。

本地复现：1–5 分评分接受 999；选项 A/B 接受 C；排序接受 `[C,C]`；指定 allowed 文件夹却抽到 other 文件夹的图。

修复：不要继续扩充一套独立抽图器。提取或复用真人问卷的纯分配模块、题型答案合同与验证器；暂时无法共用的题型明确不支持。建立“题型 + 具体设置”白名单，运行前列出不能执行的设置并阻止假完成。支持多 trial 后按 trial 保存真实 stimulus、题目 revision、答案及完成状态。

### D. Silicon 运行依赖浏览器，取消和统计也不完整【代码路径】

位置：`src/components/admin/SiliconSamples.js:123-170`；`worker-lib/silicon/runner.mjs:30-107,110-115,202-204`。

- 浏览器 for 循环不断调用 process 推进。刷新页面或切项目会停止后续调用；列表没有明确 Resume 入口。
- 一个 chunk 虽只有一个 persona，但包含其全部题目，长问卷仍是一段长 HTTP 工作。
- 查询已有答案再插入，不是原子认领；并发执行可能重复消耗模型额度。
- 只在开始 persona 前检查取消；做完后无条件写回 running，可能覆盖期间收到的 cancelled。
- persona 在执行时读取现值，没有冻结，运行中修改 persona 会破坏可追溯性。
- token budget 不是严格费用上限；输出 token 限制不能覆盖输入/推理开销，失败路径的计量也需校准。
- 已答一部分、剩余因预算跳过时可能标成 ok。

修复：后台分步执行、原子认领与幂等答案写入；明确 canceled/partial/budget_exhausted 状态且不得回退到 running；在每题/每 trial 检查取消；冻结 persona、问卷、媒体规则、模型配置和运行版本。预算采用保守预估与每次调用记账，注明预算单位与可能的单次调用超额边界。

## 3. 编辑问卷时的体验缺口

### 编辑器和 AI 看到的不是同一份状态

`useSurveyAssistant.js:635-643` 发送 currentConfig 和 enrichedHistory；`designerChat.mjs:461-473` 排队时将其丢弃。核心工具读取数据库稿，而非未保存的编辑器草稿。

`AdminApp.js:420-429` 检测到本地脏稿后只警告并拒绝载入 AI 修改。这能避免立即覆盖，但用户仍可能看到“AI 已改好，编辑器没有变化”。当前 hook 也没有选择中的 page/question/tab 上下文，不能可靠理解“这道题”“这一页”。

行动：提供 projectId、页面/题目稳定标识、当前面板、编辑基线 revision；启动写入前完成当前草稿的安全保存/协调。冲突必须可解释且保留用户输入，不靠提示用户刷新解决。模型不能拿临时 DOM 文案作为编辑目标 ID。

### 7 种操作不足以支持日常设置修改

`src/lib/platformSchema/registry.json:374` 起仅有 addPage/removePage/addQuestion/updateQuestion/removeQuestion/setAllRatingScales/replaceConfig；`modes.mjs` 又限制 adjust 不得随意 replaceConfig。

因此“改问卷中文、改整卷标题、改页面设置、移动题目、改主题”没有完整的增量操作路径。Schema 写着有字段，不等于模型有合法工具可修改。

行动：补受控的 survey/page/theme 更新、题目移动和顺序操作，配套权限、验证、inverse、schema 文档。保留未知但合法字段；不得为改一个字段而删除重建页面/整卷。

### 撤销入口未接上 Queue 主路径

`agentApi.js:242-264` 返回结果不含 surveyConfig；`useSurveyAssistant.js:779-805` 该路径只通知载入远程稿，undo snapshot 却只在另一条带 surveyConfig 的分支建立。

行动：每次写入记录 before/after revision、变更摘要和 inverse；结果卡提供“查看修改 / 定位题目 / 撤销本次修改”。撤销必须检查新 revision，不能覆盖后来人工编辑。

### 创建新项目、平台问答与结果导出没有完全接通

`platformTools.mjs` 可以创建新项目；但 `designerTools.mjs:67-131` 的读写工具固定当前 projectId。需要明确新建成功后的项目切换/下一 run，不允许刚创建 B 却继续改 A。没有项目时前端又阻止聊天，不能把“全平台助手”当作已完成。

已有结果列表与摘要工具，但站内 registry 没有 `survey_export_responses`；`survey_export_project` 是项目包，不能当成结果导出。网页中的完整结果导出流程仍需接通下载交付和过滤条件。

行动：首期优先把当前项目操作做到完整。为全局问答提供明确只读上下文和帮助资料检索；项目创建后明确绑定目标；结果回答引用版本、样本数、过滤条件、所用分析，并返回真实文件/下载入口。无需添加任意浏览器或 shell 工具。

### 审批、记忆、刷新和进度

- `ChatAssistant.js:679-695` 审批只显示工具名称，没有显示目标项目、发布版本、删除数量、参数摘要。审批必须针对具体可核对的结果。
- `useSurveyAssistant.js:298-326` 恢复处理 running/awaiting_approval，但未把 queued 当进行中。
- `agentApi.js:235` 每 750ms 请求完整 session，没有传 after；后端虽有 cursor 接口，前端尚未使用。
- `designerChat.mjs:247-253` 把事件转 UI 文本取最后 12 条，丢失跨 run 工具结构和较早约束；已有模型历史转换器不能算已接通。
- `designerChat.mjs:49` 系统提示仍统一要求随机媒体和 preset Skill，和现有固定选图/自定义 Skill 能力冲突。

行动：先修 queued 恢复、网络重连、取消/审批失败提示；再接增量事件分页和轻量 run 摘要。长对话保存可检查、可删除的研究约束与决策摘要，同时保留必要工具历史。文字可以按短时间/字节批量发送，无需每 token 落数据库。删掉违背用户设置和平台能力的硬编码提示。

旧 `multiAgentReview.js` 定义城市科学、城市设计、感知心理、测试参与者、数据分析五类角色，默认生成/调整后自动触发评审，多轮及通过比例门槛。这些知识可以变成三个按需检查：

1. 研究设计检查：题干、量表锚点、偏差、疲劳、随机化和设计要求。
2. 参与者流程检查：PC/手机媒体、trial、必答/跳题、提交和无障碍。
3. 分析与导出检查：题型答案结构、变量、缺失值、媒体关联、分析与导出兼容性。

每项输出“问题 → 对应题目 → 修改建议 → 可执行修复”，可只读运行，不自动改完整问卷。先用确定性验证检查事实，再由模型解释研究取舍；不要用多模型投票百分比伪装研究质量保证。这类检查与执行交互题的 question Skill 是不同概念，不应混用库或结果合同。

## 5. Silicon 的产品定位和结果闭环

隔离在 silicon_* 表、标记 response_source=silicon、展示不替代真人的说明，这些应保留。但隔离存储仅解决来源混淆，不解决模拟是否有效。

`getSiliconCompare` 当前只是按题聚合原始答案；UI 主要显示每题答案数量。它还不是完整的人机样本比较或研究分析工作台。

首期把它定位为“自动预试 / 模型模拟回答”：报告哪些题答不了、遗漏多少、非法答案、题干疑点、媒体/分支覆盖，以及受支持题型的描述分布。提供独立 JSON/CSV 导出，带 run、问卷版本、persona 快照、provider/model、seed、实际媒体、trial、错误/跳过和计量信息。不要把 persona 重复次数当独立真人样本，也不要默认给出可推广到人群的显著性结论。科研有效性需要单独的人类对照验证，本次代码审查无法证明。

## 6. 给 Cursor 的下一步指示

请在 update2 当前工作区继续，不切回 main、不覆盖未提交改动、不重新整仓迁移 Harness。先记录当前变更基线，按以下顺序做小范围可审查的提交；没有明确发布授权前只准备部署，不修改生产。

### 第一批：可靠保存、恢复和取消

修 A/B；补 run/tool 执行记录与必要 SQL migration；使用并发与故障注入测试，而不是只测试函数返回字段。审批卡同时补具体目标与摘要。

验收：

- 只改题干、5→7 分、选项、locale、媒体文件夹、trial 均能读回核实；旧稿/部分保存不可通过。
- 同一个 queue job 同时/先后投递两次，不能重复创建/发布/删除。
- 在“副作用完成后、checkpoint 前”和“checkpoint 后、下一条消息前”模拟失败，恢复结果明确。
- 取消后恢复已批准操作不会再启动写入；审批重复点击无重复副作用。
- 多标签页编辑冲突不丢稿，终态任务不能回到 running。

### 第二批：编辑体验真正贯通

补当前题目/页面上下文、脏稿协调、增量操作、按 run 撤销、目标项目绑定、帮助/结果导出交付；使用单一 Agent 作为默认入口。保留只读约束，将生成/调整作为任务意图或快捷入口，不要求用户理解四种内部执行模式。暂不需要重构所有模式代码。

验收：

- 编辑器选中某题，说“这题改成 7 分”，只改变目标题。
- 未保存时发起 AI 修改，人工改动被保留且双方最终显示同一 revision。
- “问卷中文、页面标题、主题色、把题移动到第二页”无需全卷重建。
- 问“这个设置什么意思”不写稿。
- 创建新项目再生成问卷，不影响旧项目。
- 展示变更列表，可定位并撤销；后来的人工作业不被静默覆盖。
- queued/running/approval 三种状态刷新均可恢复；断网重连不重复提交。
- 发布前显示实际项目和版本，并区分草稿保存、参与者发布和发布到首页。

### 第三批：Silicon 限定支持范围并后台运行

修 C/D；先建立支持矩阵，不默认支持未知类型。共用原生规则；暂不支持的复杂条件/媒体/trial 组合提前明确拒绝。冻结运行输入，补真实完成度及独立导出。

验收：

- 指定文件夹和 category 不越界；固定图不被随机替换。
- 相同输入下预试与真人的分配规则一致；记录的媒体与模型实际收到的媒体一致。
- 999 分、选项外答案、重复排序等不能写成有效答案。
- 支持的 trial/分支严格遵循配置；不支持的组合开始前说明，不在运行后假完成。
- 刷新/切项目不终止后台工作；重复请求不重复收费执行；取消状态不被覆盖。
- 运行中修改 persona 不改变已冻结的 run；预算中止标为部分完成。
- 导出可回溯到每题/每 trial，不能混入真人正式回收。

### 第四批：收尾与受控试用

- 接通事件 cursor / 历史分页；长对话约束摘要；合适粒度的文字更新。
- 把旧专家知识转为按需检查，移除不可用的旧配置入口和错误提示。
- schema 作为字段/合同生成源，浏览器、Worker、MCP 的验证/操作/结果映射做一致性测试；不能仅检查生成文件 hash。
- PC 1440/1024、手机 390/360 宽度实际走查：键盘弹出、长文本、工具卡、审批、滚动、输入保持、题目定位、PC/手机预览、后台切换。
- 测试实际目标 provider：工具调用、错误修复、上下文变长、图像输入、取消与恢复。只对实测路由承诺支持。
- 核对 update2 当前 `ai_runtime.sql`、`silicon_samples.sql` 及所依赖的项目保存迁移，确认 Queue 已创建且绑定有效。历史上“SQL 跑过”不等于跑过当前未提交版本。
- 核对生产配置和权限时不打印密钥；不要用直接 service-role 访问替代用户流程验收。
- 输出每批修改、实测案例、未解决限制与部署步骤。Assistant、Silicon 使用独立开关；未达标的 Silicon 保持实验可见范围。

最终交付标准不是“测试都绿了”，而是用户能完成：创建问卷 → 调整指定题目/设置 → 核实保存 → 预览 → 撤销/冲突处理 → 明确发布；以及另一路可追溯、真实标注支持边界的 Silicon 预试与导出。
