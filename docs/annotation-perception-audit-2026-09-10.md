## 优先处理：保存与身份

### 1. 自动保存可能被切图或离开页面取消（P1）

MediaPreannotatePanel.js:270–312 的保存延迟为 700ms，effect 清理会取消计时；Next/Previous 仅根据位置和 batchBusy 禁用，并不等待保存。已经开始的请求也没有序列化和当前图片校验，旧请求完成可能更新新图片的保存状态。

建议：以固定 media_id 捕获每次保存的快照；按图片排队；切图/离开时先提交待保存内容；失败保留本地待重试草稿；状态区区分待保存、保存中、失败，提供重试。

### 2. 加载失败与无标注混为一谈，特征 CSV 有覆盖风险（P1）

imageFeaturesR2.js:319–350、411–429 把读取错误吞掉并返回空值；保存特征时以读取结果为基础重写整个 CSV。读取失败后继续写，可能用局部数据覆盖已有特征。并发 accept/undo 等操作会调用同一 CSV 的读-改-写，缺少跨请求并发保护。JSON 成功、CSV 失败时也会留下两份结果不一致。

建议：只有真实不存在返回空；权限/网络/解析失败应阻止覆盖并给出重试；改为每图片权威记录、可重建汇总，或由服务端完成带并发控制的更新。批量操作失败后应能继续，不应先永久关闭批次再逐张写。

### 3. 标注路径和结果关联仍依赖可变名称（P1）

imageFeaturesR2.js:65–87 以 folder/name 派生标注路径；逻辑移动文件夹会改变该路径。回退读取旧 basename 也不能唯一辨别同名图片。中文路径经过替换可能碰撞。imagePerceptionJoin.js:80–90 对若干结果匹配使用 basename + find，第一个同名文件可能被错误命中；annotation 聚合有 image URL 时也走此路径。

建议：统一以不可变 media_id 存储和关联；优先使用回答记录中的 shown_media_ids；历史数据只能在唯一匹配时回退，并列出无法确定的记录。兼容迁移旧路径，不能简单切换后遗失既有标注。

## 优先处理：特征与分析口径

### 4. 中文标签会合并（P1，纯函数已复现）

imageFeaturesR2.js 的 samLabelKey 仅保留 a-z/0-9；“树木”“建筑”均得到 unlabeled。派生 SAM CSV 中不同中文标签会合成一列，人工界面仍显示不同标签，容易忽略。

建议：标签使用稳定 ID，保留原始中英文显示名；导出标签字典。兼容已有英文列，必要时从原始 shapes 重建派生特征。

### 5. 面积字段不是去重后的覆盖率（P1，纯函数已复现）

deriveSamPreannotFeatures 对形状面积求和再截断到 1。两个完全重叠、各占图像 25% 的 bbox 得到 sam_ratio_tree=0.5，实际联合覆盖率应为 0.25。

建议：分别输出对象数、面积之和、区域并集覆盖率，并明确 bbox 面积与分割区域面积的区别；不要让不同含义共用一个未说明的 ratio 字段。

### 6. SAM 的零值与缺失值未区分（P1，纯函数已复现）

perceptionFeatureValue 对已完成 Seg 中不存在的类别补 0，却对已完成 SAM 中不存在的类别返回 null。相关计算会排除这些图片，模型流程可能填补中位数。仅有树木的已标注图片，建筑数量应为 0；未标注/未审核/提取失败则不能直接视作 0。

建议：先明确审核状态与标签适用范围，再对明确完成的标注补零；图表、模型与导出使用同一取值规则。

### 7. 审核状态、版本与可复现导出尚未贯通（P2）

review_status 保存在标注 JSON 中，但派生特征记录不带审核状态；分析按 SAM ready 筛选，不能选择仅纳入 Accepted。结果问卷已有版本筛选，但 ImagePerceptionPanel 读取的是当前项目媒体与当前 R2 特征，旧问卷版本不等于旧特征快照。wide CSV 未记录完整筛选条件、标注/特征版本和指标字典；图表中补零的 Seg 类别在直接导出原始行时仍可能留空。

建议：提供审核筛选、匹配覆盖报告、特征更新时间/版本；明确当前特征分析与冻结数据集；导出相同分析矩阵和一份方法/来源清单。

### 8. 方法适合探索，但显著性解释还需收紧（P2）

已有 Pearson 相关、比较题 TrueSkill、训练/测试划分与交叉验证。perceptionAblation 的缺失填补、缩放和筛选在训练 fold 内完成，这是值得保留的基础。

当前相关性逐个计算原始 p 值并标星，没有多重检验校正；图片均值分析也未处理同一参与者重复评分及图片之间的场景相关性。不能直接把这些图当作因果证据或最终论文结论。media* 题型在题目列表中被整体排除，虽然部分聚合函数已有分支，实际支持范围与“any image-question”文案不一致。

建议：默认称为探索性关联；展示有效图片数与评分量，添加校正后的 p 值；按需求提供 Spearman 和不确定性估计。预测泛化应可按地点/场景分组验证，并导出种子与拆分信息。优先补齐使用图片的 media* 题型和标准 Skill 结果映射，不必继续增加模型数量。

参考：
- [SciPy：多重检验与 FDR](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html)
- [scikit-learn：交叉验证与分组验证](https://scikit-learn.org/stable/modules/cross_validation.html)

## 交互完善（P2）

- 手机：上一张/下一张移到画布上方或下方，让图片占满可用宽度；工具栏分组折叠；提供放大/平移和明确的浏览/绘制模式。当前 canvas touchAction:none 会拦住画布内的页面滚动，需要有可理解的退出方式。
- PC：保留现有绘制、SAM 辅助、批处理；提供真正的 Undo/Redo。当前 ImageAnnotationWidget.js:983 的 Undo 只取消草稿或删除最后一个形状，不能撤销顶点移动、改标签、删除和清空。
- 标签与分析中仍有大量固定英文、模型内部名称，应该换成易懂说明并跟随后台语言。

## 已实施与验证（同日，用户批准后）

- 保存：按项目和媒体 ID 排队，捕获编辑时的快照；切图和离开提交待保存内容；失败保留浏览器恢复草稿并支持重试。同一图片在当前页面进程内顺序写入，不同图片不再争抢一个共享 SAM CSV。批次在各图片保存成功后才关闭。
- 存储：新标注以稳定 ID 写入 `preannotations/by-id/`；兼容读取身份能匹配的旧路径。后台列举标注 JSON，SAM 汇总由权威 JSON 重建。网络、权限、解析失败明确报错，不作为空标注覆盖。
- 特征：中文标签使用无损键并导出字典；数量、面积之和、并集覆盖率分开；已保存的零形状记录保留；只有 v2 标注的已知标签才可把缺少类别解释为零。保留旧 CSV 独有记录并标记 legacy，不能凭旧 CSV 恢复丢失的几何语义。
- 编辑：真实 Undo/Redo 覆盖清空、删除、标签和顶点移动；手机切图按钮单独成行，支持工具折叠、100–400% 放大、浏览/平移模式，修复折叠或调整视口后遗留的大段空白。
- 分析：使用稳定媒体身份，歧义名称不猜测匹配；加入 media rating/boolean/ranking 的题目选择；多图片组级评分不复制为每张图片的评分。审核筛选、覆盖计数、分页、中文标签显示和加载失败重试贯通。
- 统计：新增 Spearman、BH-FDR、多重检验校正后的星号和 Pearson 95% Fisher-z 区间。额外发现并修正原 Pearson p 值所用不完全 beta 函数的符号错误，采用稳定连分式计算，移除大样本正态近似分支。**此前该面板生成的 p 值与显著性星号应重新计算和导出。**
- 建模：保留训练 fold 内的预处理，支持按文件夹分组验证，导出随机种子及每次 train/test 媒体 ID；完全没有可用特征的评分记录不能用中位数虚构整行，界面显示有效建模数量。
- 导出：CSV、图表和模型使用相同零值/缺失语义；分析 JSON 保存实际输入矩阵、相关结果、审核/特征筛选、方法、回答 ID、问卷修订信息、特征时间和字典。标注 ZIP 仅包含所选图片的派生特征，同名文件不互相覆盖，图片下载失败写入 manifest 并显示。

### 部署与保留边界

- 本轮不需要新增 Supabase SQL。前后端必须同时更新：Node/Worker 的 R2 list 新增 annotation index；前端检测旧后台会明确提示更新。本地 3000/3001 已重启。尚未提交、推送或部署。
- 此处分析仍使用当前标注/特征；问卷版本不会自动冻结媒体特征。下载的分析 JSON 保存导出时的输入，可用于复核该次分析。
- 同一图片被不同设备同时编辑仍无服务端 CAS/冲突合并；本轮解决当前页面的顺序保存及不同图片的共享文件覆盖问题。多人同时修改同一图片仍需协调。
- 相关结果是图片层面的探索性分析，不建模参与者重复评分依赖；分组验证仅在文件夹确实表示地点/场景时才有意义。Spearman 的小样本 p 值仍为近似，未实现所有 Skill 答案类型的图片特征映射。
