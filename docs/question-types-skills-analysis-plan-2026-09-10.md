# 题型、设置、Skill 与结果分析：第二轮审查及实施计划

日期：2026-09-10。范围：当前本地 main，包括上一轮已推送的体验／导出修复，以及尚未提交的管理员结果入口。忽略 update 分支。本轮只审查并制定计划，不修改业务代码、问卷或真实答卷。

## 结论与边界

现有题型已经覆盖日常问卷和主要视觉／媒体评价任务。QuestionEditor 列出 33 个基础类型、7 个内置交互任务，另可选择自定义 Skill。覆盖广不等于所有设置组合和统计方法都已验证。

建议保留 Skill 的自定义交互运行能力、版本和标准答案协议，将用户面对的 Skill Library 简化为“我的自定义交互”。普通用户按任务选择题目；已有交互不要求先复制进库；只有改交互逻辑时才创建自定义版本。暂停扩大公共库和让自定义任务自行编写统计分析。

目前更急的是统计实现、设置校验和自定义 HTML 隔离。前次 286／288 项回归主要验证流程及数据匹配，不能替代数学参考实现对照。本次使用独立合成案例查出了新的统计缺陷，不重复列出上一轮已经修复的问题。

结果页对已加载答卷随筛选即时重算；新增答卷需要刷新，不是实时订阅。计算快、指标名称正确和统计结论有效是不同问题。

## 题型与默认分析应如何对应

| 题型家族 | 当前覆盖 | 建议默认呈现／限制 |
|---|---|---|
| 文字输入、长文本 | 有原文与长度统计、导出 | 保留原文、有效回答数；暂不增加自动主题解释 |
| 数值、评分、滑杆组 | 分布、均值、SD、中位数及部分一致性 | 区分数值与等级评分；明确量程、单位、每个维度样本数；一致性只在重复评价相同对象且满足条件时出现 |
| 单选、下拉、复选、是否、同意 | 频率、比例；是否题已有 Wilson 区间 | 选项保留零频率，明确“占回答者／占选择次数”；未知选项和缺失不按有效类别混算；重复测量不能直接当独立样本解释区间 |
| 矩阵 | 行列分布、数值列均值 | 默认逐行分布；只有确实是数值尺度时显示行均值，不能因内部编码为数字就认定具有间距意义 |
| 普通／媒体排序 | 平均名次、Borda、Kendall W、媒体 TrueSkill | 完整且相同选项集才能用当前 W 公式；不同子集按任务集描述或使用经验证的比较模型 |
| 图片／媒体选择、强制 A/B、偏好滑杆 | 选择率、比较排名、偏好分布 | 选择率为默认；TrueSkill 修复后作为探索排序；A/B 方向、平局、未选与题目语义必须明确 |
| Best–Worst | 展示数、best/worst 次数、净 BWS、比较排名 | 默认展示归一化净选择次数；当前 BWS 是计数分数，不等于估计了离散选择模型的效用 |
| 点数分配 | 各选项均值和所谓预算合规 | 区分“不超过预算”与“必须用完”；分别报告合法比例和全额使用比例 |
| 空间标注 | 叠加、密度、形状／标签统计、原始几何导出 | 说明坐标归一化、每人／每形状的统计单位；标注数量不自动解释为人群比例或真实注视 |
| 视频时间段、连续视频评分 | 时间轴与逐样本统计 | 每人每时间桶先聚合，时间段先合并；同时显示覆盖人数，避免设备采样频率决定权重 |
| 颜色映射 | 颜色、色相、强度等描述 | 保持探索性表述，不把色相分类当通用心理量表 |
| 说明／图片／媒体展示 | 不收集普通答案 | 从回答率分母排除；保留展示上下文 |
| 自定义交互 | 单字段标准答案映射到上述家族 | 平台负责验证、分析和导出；交互 HTML 负责呈现及收集，不另建统计系统 |

## 已复现和已定位的问题

### 1. TrueSkill 更新符号异常（优先修复）

位置：`src/lib/trueskill.js:27`、`:118`。

当前以胜者减败者的标准化差值 t 作为输入，但 v 的分母使用 Φ(-t)（eps=0），与获胜更新方向不匹配。合成案例：A 连续胜 B 三次后，同样初始状态下 A 再胜一次，μ 增加约 11.4534；A 爆冷输一次，μ 仅减少约 0.0005898。预期容易发生的胜利反而得到极大更新，意外失败影响极小。

影响图片／媒体选择、媒体排序、强制选择、Best–Worst 的共享比较排名。应对照参考算法修正 v、w 与动态方差设置，增加同实力、强者胜、弱者胜、极端差值和有限数值测试；未经验证不要把 σ 当频率学置信区间。当前是成对更新近似，多项任务拆出的多对比较也不等于多个独立受试者。

`attachMuStd5` 的 0–5 是当前题目样本内 min–max 缩放，筛选或媒体集合变化时会改变。应标为相对展示分，不能与直接收集的 1–5 量表或其他项目横向比较。

参考：[Microsoft TrueSkill](https://www.microsoft.com/en-us/research/project/trueskill-ranking-system/)。

### 2. Krippendorff α 未正确处理不同评分人数（优先修复）

位置：`src/lib/reliability.js:57`。

当前直接平均所有单位内评分对的差异，评分人数多的单位获得组合数权重，缺少标准 coincidence 构造中按单位评分人数减一的归一化。

复现：对象 A 的评分是 [0,1]，对象 B 是 [0,0,0]。nominal α 当前为 0.375，按标准 coincidence 权重为 0。后者观察不一致度为 2/5，期望不一致度为 2/5。

还需声明 ordinal／interval 选择、重叠对象数量、重复参与者处理及常量数据不可识别情况。不要仅凭 α 阈值将真实意见分歧直接判为坏数据。

参考：[Krippendorff 原作者计算说明](https://www.asc.upenn.edu/sites/default/files/2021-03/Computing%20Krippendorff%27s%20Alpha-Reliability.pdf)。

### 3. 不同媒体子集仍计算 Kendall W（优先修复）

位置：`src/lib/rankingStats.js:26`；`src/components/admin/ResultsAnalysis.js:956`。

媒体按 trial 抽样时，分析将所有出现过的媒体取并集，再套用完整共同排序的公式；未出现在某轮的媒体隐含贡献零名次。两人分别只排序 [A,B] 和 [C,D]，仍得到 W=0.05，并可显示一致性解释；这些并非同一对象集合的两次完整排名。

应验证每份排序对同一项集完整、无重复且满足当前无并列公式；不满足时不显示该指标。可显示每个任务集的平均名次，但不同选项数量、不同对手池之间不直接比较 Borda／平均名次。参与者重复 trial 也要区别于独立评审人数。

参考：[NIST 关于多组共同对象排序的定义](https://www.itl.nist.gov/div898/handbook/semstat/semstat-doc.pdf)。

### 4. 视频覆盖比例和连续评分权重（优先修复）

位置：`src/lib/videoStats.js:5`、`:128`。

一位参与者标记 [0,2]、[1,3] 两段，重叠时间桶得到 proportion=2，即 200%。内置题可以添加时间段，汇总未先对同一答卷合并。若指标表示“标记人数比例”，应每答卷每时间桶最多计一次；若保留事件密度，应改名和单位。

连续评分按所有采样点混合平均。一个人同一秒评分 0 采一次，另一个人评分 100 采三次，当前 mean=75、n=4；按参与者等权应为 mean=50、人数=2。先统一每人时间桶内聚合／插值规则，再跨人汇总，并显示实际覆盖数。

### 5. 点数分配的合法规则与“合规率”不一致

位置：`src/components/SurveyCustomComponents.js:1287`；`src/components/admin/ResultsAnalysis.js:2221`；`src/lib/questionSummaryExport.js:2021`。

作答允许总分不超过预算，但页面与导出只有总分等于预算才算 compliant。预算 100、合法分配 50，会被显示为未合规。应沿用当前“不超过”默认行为，把全额使用率单列；如果以后允许设置“必须用完”，前端验证、Skill 合约、分析和导出要使用同一个配置。

### 6. 原生设置校验不足，存在零值和选项标识问题

位置：`src/components/admin/QuestionEditor.js:878`、`:2376`；`src/lib/designProtocol/validate.js:13`。

- 评分最小值 UI 使用 `rateMin || 1`，合法 0 会显示成 1，形成显示和保存值不一致。
- 新增选项根据文字转小写、空格转下划线生成 value，没有唯一性检测，例如 `A B` 与 `A_B` 得到相同内部标识。矩阵行／维度也应检查稳定唯一 ID。
- 合成配置中 rateMin=5、rateMax=1，外加重复选项 value，共享验证器返回 valid=true，errors/warnings 均为空。证明共享验证层不足，不代表所有运行时控件都接受这些值。
- 缺少完整的量程、步长、预算、空矩阵、选项数量与配置冲突检查。已有媒体数量约束应复用，不应再写多份不一致规则。

建议先补一个共同题型校验入口，供 Builder、MCP 和保存流程使用。对已有答卷的题目，改标识和语义应提醒版本影响，不能自动改写历史答案。

### 7. Skill 声明校验不等于真实答案校验

位置：`src/lib/skillResultTypes.js:422`；`src/components/SkillQuestionWidget.js:111`。

现有保存流程已经要求一个标准结果字段、exampleAnswer、固定版本和官方 SPSkill 协议，也禁止新合约自定义 analysisHtml，应保留。

但检查器只把字段类型传给验证函数，不核对字段 min/max、options 等设置。复现：声明 rating 1–5 时 {score:99} 得到 ok=true；options=['a','b'] 时未声明选项 'outside' 也得到 ok=true。参与者 iframe 消息被接收后直接写答案，resultSchema 未作为运行时的完整准入检查。

应新增真实作答验证：合法范围、有限数值、选项归属、排名唯一性／完整性、预算与媒体 ID；在宿主边界验证后再标记该题已完成。旧答卷保留原始值，将不合约值明确标记，不静默裁剪或删除。服务端提交路径也应设计对应校验；不能将客户端校验视为防篡改保障。

### 8. 自定义 HTML iframe 隔离需收紧

位置：`src/components/SkillQuestionWidget.js:186`；`src/lib/skillSdk.js`；`src/lib/skillHtmlValidate.js`。

当前 srcDoc 同时允许 scripts 和 same-origin，HTML 检查主要检查 SDK 约定，未构成独立安全隔离。对平台加载的第三方或 AI 生成 HTML，这是具体配置风险。本次没有在真实用户会话中运行绕过代码或读取任何敏感数据。

应测试移除 allow-same-origin 的兼容性，保留 postMessage 协议并核对发送方；必要时采用独立来源的运行器。添加受限 CSP，按已选媒体来源授权加载，禁止自定义任务任意联网、导航及访问宿主存储。公共模板审核保留，但审核不能代替运行时隔离。

参考：[MDN iframe sandbox 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)。

### 9. 高级特征建模在拆分数据前预处理

位置：`src/lib/perceptionAblation.js:1009`、`:1018`、`:1035`。

代码先在全体数据上做 VIF 筛选、常量列筛选和标准化，再进行 holdout／K-fold。验证折的信息进入训练前处理。应将需拟合的预处理移入每个训练折，仅用训练参数变换验证折。此问题通过代码顺序确认；本轮没有量化真实研究数据上分数受影响程度。

高级模型先标明探索用途，修正后再宣传泛化性能。若需要推广到新街区、来源或参与者，应按研究设计选择分组验证，不自动把随机分行验证当作所有场景的泛化能力。

参考：[scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html)。

### 10. 文档与真实导出形状仍有局部不一致

Skill analysis guide 对排序描述为“每个 rank 一行”、对标注描述为平铺坐标，但部分原生适配出口仍以完整排序或形状 JSON 表示。上一轮保留标签和路径时间已经解决信息丢失，不等于已经实现了这些平铺格式。MCP 文档应由实际导出样例核对或生成，防止 Codex 依据错误约定写后处理脚本。

## 题型设置体验的轻量简化

不改底层 type 和历史数据，只调整创建入口：

1. 先选任务：填写／选择、评分、比较／排序、标注、视频任务、展示说明。
2. 再选刺激：无媒体、图片、视频／音频／混合。系统映射已有类型，隐藏不支持组合。
3. 编辑分为“题干与答案”“媒体与轮次”“高级设置”；保留现有预览和抽样工具。
4. 同屏多个刺激但只填一个答案时，明确显示“对整组评价”；若要每张分别评分，提示使用单媒体多轮，避免暗示有独立多图评分。
5. 保存前显示实际工作量和数据定义：例如每轮 2 张、共 10 轮、单选、每轮记录一个媒体 ID；说明缺媒体、重复策略和最终可用样本量限制。
6. 一屏提供小型联动预览：模拟答一次 → 查看记录值 → 查看对应图表和导出字段。模拟数据只存在预览中，不进入真实研究答卷。

需要明确“输入表单美观”和“参数不会造成无效数据”两个验收维度。表单外观整理排在校验修补之后。

## Skill 的推荐产品形态

保留：HTML/JS 自定义交互、标准 SDK、resultSchema、不可变 revision、私有复用、可选公开审核、MCP 创建和更新。

简化：常用任务只在题型菜单中出现一次；库主要保存研究者自己改过的交互，不把现成题型再复制一遍。标题改为“自定义交互”，放到高级入口。暂不建设庞大公共市场、评分排名、复杂分类或每个 Skill 独立统计代码。

Codex 的工作顺序：先使用现有原生设置；确实需要特殊呈现时，先确定标准输出，再生成交互。例如：

- 看图片 500ms 后遮挡再评分 → rating，声明量程；
- 点击认为不安全的位置 → points，声明坐标和标签；
- 拖拽照片排喜好 → mediaRankedList；
- 记录完成某操作的耗时 → number，明确单位 ms；
- 混合多种独立任务 → 拆题，或使用已有受支持的 compositeBlocks，不随意堆 JSON。

平台统一处理题号、语言、进度、提交、保存、分析、导出；Skill 管理交互呈现和标准答案。选择输出后自动生成 schema、默认配置和示例答案，普通使用者不必填写数个 JSON 文本框。新建页的默认交互应当与默认 schema/example 一起构成可保存、可预览的有效示例。

多轮还有一个限制：当前 `TRIAL_LOOP_TYPES` 未包含 `skillquestion`。自定义 HTML 内部重复任务，不等于平台已经得到逐轮记录。短期必须说明该限制；确需多轮时再把符合合约的任务接入统一 trial 层，不能让 Codex 在一个答案字段里悄悄聚合多轮并丢失上下文。

## 分阶段实施计划

| 阶段 | 范围 | 可验收结果 |
|---|---|---|
| 第一批：可信度修复 | TrueSkill、α、W 条件、视频按人聚合、预算语义、Skill 隔离与实际答案校验；高级建模预处理 | 合成反例转为正确输出或明确“不适用”；与参考实现一致；异常 Skill 不访问宿主；原始答卷不被修改 |
| 第二批：设置防错 | 量程／零值、选项／维度唯一 ID、媒体约束、缺媒体与工作量提示；Builder/MCP 共享规则 | 同一配置通过两种入口获得一致验证；无效配置能定位到具体字段；旧题目变更不静默改语义 |
| 第三批：收简入口 | 任务优先的题型选择、自定义交互入口、有效默认模板、模拟答案与结果联动 | 普通研究者无需进入 Skill 库即可完成内置任务；Codex 自定义任务先有标准答案，再有交互 |
| 第四批：收尾验收 | 各题型家族最小样本、边界设置、390px/桌面、恢复／多轮、分析／导出一致性 | 每种指标写明统计单位、有效 n、缺失规则、版本与算法版本；主要家族完整走通创建→作答→分析→导出 |

第一批可以拆成多个小提交，避免和菜单整理混成大改。修正算法可能改变已有图表和重导出的数值，要增加 analysis_algorithm_version 与变更说明。优先用原始记录重算；原始记录缺失的旧数据明确不可恢复，不猜测补全。

暂缓：新增大量题型、公共 Skill 市场、任意自定义分析脚本、自动显著性结论、大规模因子分析／结构方程模块。若研究者确实需要推断分析，先按具体研究设计补少数经过验证的方法，或导出到成熟统计工具。
