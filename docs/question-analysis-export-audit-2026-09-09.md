# 题型、结果分析与导出匹配审查

修复进展：本报告保留审查时的结论；后续实施与验证见 [2026-09-10 修复记录](main-experience-fixes-2026-09-10.md)。

日期：2026-09-09。范围：当前本地 main（含已有未提交修改），不涉及 update。此次为代码审查和合成样本验证，没有修改业务代码、问卷或真实答卷。

**结论：入口覆盖较完整，数据语义和边界组合尚未完全对齐。** Builder 有 33 种基础类型（含 3 种展示题）、7 个内置交互任务及自定义 Skill。原生作答题和 7 个内置任务均能找到分析与导出分支，但这不代表每种配置都经过完整端到端验证。应先修正下面的数据缺口，再补少量说明和操作反馈，无需大改平台。

**逐类对照**

“路径齐全”指存在匹配的分析和导出实现；不是宣称所有配置、历史数据、移动端都无缺陷。多轮媒体题共同受下文媒体集合／类别导出问题影响。

| 题型 | 页面分析 | 导出内容 | 判断 |

| text、comment | 原文、文本长度等 | 原文长表、长度汇总、宽表 | 路径齐全；无需急于增加自动文本分析 |
| number、rating（含 text + inputType=number） | 数值分布／评分分布 | 数值、均值、标准差、中位数、极值、计数 | 基础匹配；评分一致性另有适用性限制 |

| imageslidergroup、mediaslidergroup | 按维度切换、按媒体汇总 | 每维度长表、属性汇总及分文件 | **只归第一份媒体；一致性计算不支持对象答案** |

**优先修复：会造成空统计、字段损失或误读**

1. **多轮媒体排序的汇总为空。** `questionSummaryExport.js:799` 的 `parsePayload` 对多轮返回数组；`:1744` 的排序分支仍把返回值当单对象读 `payload.answer`。用一人、两图、两轮相反顺序的答卷，long 有两行，summary 为 `[]`。界面使用展开后的答案，代码路径不同。应统一从逐轮 answer units 计算；混合单次／多轮历史答卷也需回归。

2. **多轮 long 导出遗漏媒体集合和类别。** `questionSummaryExport.js:805` 起的多轮分支把 set、group、categories 设为空，即使原答卷顶层保留了这些值。样本单次输出 `day/urban`，换成两轮后两行均为空。`enrichSurveyResponses.js:95` 保留的是题目级集合／类别，修复时要区分可安全继承的题目级上下文和真正逐轮变化的上下文，不能盲目给每轮复制最后一轮的类别。

3. **同屏多媒体的答案归属规则不一致。** Builder 允许矩阵、滑杆组、分配题显示 1–6 份媒体；页面和汇总却只读取 `shown_images[0]`（ResultsAnalysis.js:486、1986、2114；questionSummaryExport.js:1652、1864、1907）。同样展示 A、B 后回答一次，A 出现在汇总里，B 不出现。评分／是否／文字标签则归给所有展示媒体。应先明确当前问题是在评价“整组刺激”还是“单个刺激”：可用一条说明及组合媒体标识修正解释，或对单媒体语义的配置做约束；不要把一次整组回答当成多个独立样本。

4. **宽表会改写文字标签。** `responsesWideExport.js:73、179` 对所有图片题的字符串／数组调用 `urlToName`。标签 `safe/quiet` 在 long 中完整保留，宽表变成 `quiet`；`?` 后内容也会被截断。仅在答案确实代表媒体地址时做显示名称转换，文本值原样保留。

5. **自定义空间／时间字段有信息损失。** `skillNativeAdapter.mjs:108` 把点转换成 `{x,y}` 后才读 `point.label`，导致合法的点标签丢失；path 的可选 `t` 也被丢弃。`questionSummaryExport.js:1090` 起的 timeRanges 对应分支导出 start/end，未导出合法的 segment label。样本分别复现 `tree → 字段名 v`、`t=123 → 缺失`、`traffic → long 中缺失`。这是分析适配／逐题导出的损失，**不等于数据库原始答案或所有导出都已丢失**；宽表原对象可能仍可恢复。应保留附加字段并增加可分析列。

6. **不同媒体可能因同名合并。** 汇总和多处图表用文件末段作为 identity（`questionSummaryExport.js:746`，`reliability.js:5` 等）；long 也只保留显示文件名。两份不同 URL `/day/001.jpg` 和 `/night/001.jpg`，分数 1、5 被合为一份 `001.jpg`，均值 3。此问题在项目确实存在同名媒体时触发，本次未断言用户项目已有此类数据。适合小范围加入稳定媒体 ID／完整来源列，展示继续用简短名称。

7. **完成人数与提交数口径不一致（延续上一轮发现）。** `buildQuestionCardProps` 给出 `pool.length`，`QuestionCard` 按 participant_id 去重后作为已答数量；同一个人两份完整提交可能显示 50%。应分别显示参与人数、提交数、有效 trial 数，完成率使用同一口径。不能拿一个含多个 trial 的长表行数直接当人数。

**第二批完善：分析适用性与可解释性**

- **滑杆组的一致性入口实际不支持其答案。** `reliability.js:15` 仅消费 number/string，忽略维度对象；`IrrSummary` 为 null 时直接不显示。两人同一图不同维度值，输入矩阵仍无 units。应按维度计算，或清楚显示“该题型暂不支持”；普通无媒体评分也需要定义可比较的 unit。
- **重复轮次一致性计算会覆盖。** 同一提交对同一媒体先评 1 再评 5，`unitMap[media][coder]` 最后只留 5。必须明确采用聚合、首次／末次还是单独重复测量统计；规则应写入结果页和导出说明。本次未做统计公式的独立正确性审计。
- **媒体 number 被显示为 1–5 评分。** 自定义 `number` 字段有媒体配置且未设 min/max 时，`skillFieldNativeQuestion` 产生 `mediarating, rateMin=1, rateMax=5`。若合法值为 37.2，图表仍标 `/5`。应使用数值统计展示，或要求并正确说明量程，不能静默假设评分范围。
- **宽表／长表用途需要更明确。** 多轮宽表主动留空维度／名次子列，信息在 `__trials_json`；这不等于未作答。下载处用一行说明“Excel 总览选宽表，逐轮建模选 long”。后续可把 ranking 增加显式 rank 列、标注增加 shape_id／point_index／坐标列，无需改现有存储。
- **把分母说明带入图表与 CSV。** 区分“选择次数”“回答该题的提交数”“看到该媒体的 trial 数”；百分比零到一的导出约定、样本量不足、筛选后的空结果应有提示。
- **补齐已有指标的导出，而不是堆新图表。** 预算合规、有效／无效答案数量等页面已有结果可写入 summary。一致性结果已有 methods.txt 路径，可进一步补为明确的机器可读指标；不应把它误描述为完全没有导出。
- **保存问卷版本信息。** 导出 manifest 已存在，但对历史答卷的解释还应关联真实作答版本，避免改题目／选项后用当前配置解释旧值。这与上一轮平台审查中的版本来源问题相同。

**现有导出基础应保留**

已经有整体 ZIP、responses_wide.csv、逐题 long／summary、按属性拆分汇总、data_quality.csv、methods.txt、manifest.json 和 README。CSV 使用 BOM 和字段转义，Skill 也有原生映射与回退。因此这次不是建议新建导出系统，而是修正共同数据读取、保留上下文，并增强说明。

**验证记录与边界**

- 跑了相关的 14 个既有测试套件（60 个断言测试），以及一个临时审查套件（13 个合成样本测试），共 **15 suites / 73 tests 通过**。
- 临时测试断言的是上述缺陷的实际输出，用于确认复现，**通过不代表缺陷已修复**。临时测试已移除，不把错误行为固定成正式回归预期。
- 13 个样本覆盖：图片／媒体多轮排序 2 个，三种多媒体属性题 3 个，trial 上下文、文字标签、空间字段、媒体数值映射、同名媒体、滑杆组一致性、重复轮次覆盖、时间段标签各 1 个。
- 检查是代码、现有测试及合成数据层面；没有逐个实际创建并提交全部 40 个内置题型，也没有验证真实研究数据的全部历史形态。
- 保留原有所有本地修改；本轮新增此文档，未修复上述业务缺陷，也未提交或部署。

建议先做一轮小型“结果可信度修补”：多轮排序、媒体上下文、文字标签、统计分母；随后明确多媒体归属、补自定义字段和稳定媒体标识；最后再完善说明与下载反馈。与前一轮 PC／移动端建议合并时，这些数据问题应排在新增图表之前。
