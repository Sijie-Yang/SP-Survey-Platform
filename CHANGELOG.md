# Changelog

Notable changes for researchers using SP-Survey. Versions follow [docs/RELEASING.md](docs/RELEASING.md); a change in how numbers are computed is always listed under **Changed results**.

## Unreleased

### Changed
- An SP-Scheme page whose `sp-scheme` block fails the check (including JSON that does not parse) is no longer imported as it is: the check lists the problems, with the line where the JSON breaks, and nothing is imported until they are fixed. Before, such a page was imported as it is and every answer the page sent was dropped. Pages without an SP-Scheme block are still imported as they are.
- MCP `media_delete` also removes the deleted files from the project media library (before, participants could still be drawn them as broken images) and can delete a whole `folder`, so a template's images can be replaced: delete the folder, then upload or import your own.
- MCP `survey_apply_operations` refuses question and page edits on a study that is one SP-Scheme page (only `updateSurvey` and `setTheme` work); edit the page and import it again. Before, a required question added this way never appeared and no participant could submit.
- MCP `survey_create_from_template` copies the template's media into the new project (`copyMedia: false` skips it). `updateQuestion` and `removeQuestion` operations find the page by the question name when `pageName` is left out.
- Publishing through MCP or the in-site assistant is refused while the project media library is empty but questions (or an SP-Scheme page) draw images from it: a published version never uses preview images, so participants would see none. Studio and the classic editor already checked this.
- Copying a template's media into a project (MCP media_import_from_template, project duplicate, save as template) now copies several files at a time and skips files already copied. The MCP import stops starting new copies after 35 s and registers what it copied, so a large template is copied over a few calls instead of timing out with nothing in the media library.
- Weekly paper scan also backfills older papers: one publication year per week, walking back to 2000, as candidates only. Crossref year filters now use full dates. New docs/scheduled-jobs.md lists every recurring job.
- Templates are edited only online: 平台管理 → 模板管理 no longer has 导入内置模板 or 导出全部, and `public/project_templates/` is a frozen backup (read only as a fallback).
- Removed the GitHub Pages deploy workflow, which failed on every docs change; the site deploys through Cloudflare.
- Licence: source code is now under MIT; documentation, survey templates and research data stay under CC BY 4.0.

### Added
- MCP for platform admins: `template_delete` permanently deletes a template and its media (needs `confirm: true`); papers linked to it are unlinked and stay in the paper library. No SQL.
- **工作台 / Studio** (`/studio`): a simple workspace beside the classic editor. One screen per study: drop the page an AI built (`.html` or `.zip` with images, checked the same way as SP-Scheme upload), see what participants see, upload images, publish, copy the link and QR code, see the response count and download data. New studies start from "让 AI 做问卷" or "自己逐题搭建" (classic editor). Signed-in researchers land here; the classic editor (`/admin`) is one click away and opens the same study (`/admin?project=<id>&tab=…`).
- Classic editor: white top bar in the homepage style, with a 工作台 button that saves first.
- MCP follows SP-Scheme end to end: `sp_scheme_spec`, `sp_scheme_upload_url` + `sp_scheme_import` (upload a page or zip, images go to the library), publish returns the participant link, `survey_download_url` gives a short-lived ZIP of the data (CSV + raw JSON + README) for the agent to analyse. Platform admins can publish a project as a public template with `template_publish`. Limits: 25 MB zip, 60 MB unzipped, 500 images per import, 20,000 rows per download.
- Publishing an SP-Scheme page with no question pages needs `supabase/release_site_pages.sql`.
- MCP for platform admins: `paper_list` / `paper_save` (add, update, approve papers and link each to its template), `news_save` (news drafts), `wiki_submit` (SP-Wiki pages as pending submissions). `survey_get_template` also says where a template's images are served from.
- Weekly paper scan: every Monday the site searches Semantic Scholar and Crossref and adds new papers to the paper library as candidates (not shown on /papers until approved). 平台管理 → 论文库 lists them under 待审核候选 with 通过 / 拒绝. No SQL.
- Fixed: adding `https://sp-survey.org/mcp` as a claude.ai connector failed with "Unknown client_id".
- Sampling mode **Balanced** on an image question now does what it says. Each participant is handed a number by the platform (0, 1, 2, …) and gets that number's stretch of the question's own library, laid out in a fixed shuffled order and repeated; so after any number of participants every image has been shown the same number of times (give or take one), nobody sees an image twice, and the same number always gives the same images. It works per question, with the question's existing settings (images per trial, trials, folders): several balanced questions in one survey are each balanced on their own library, and balanced questions that draw from the same library share it so a participant does not meet the same image in two of them. Fixed sets (one tagged folder = one set) are balanced the same way, set by set. A number someone started and left is handed out again after 30 minutes; a reload keeps the participant's number. Responses record it in `survey_metadata.balanced_draw` (`claim: server`, or `local` when the platform could not hand out a number and the draw was plain random). No new settings. Needs `supabase/balanced_draws.sql`; until it is run, balanced questions draw at random as before.
- Recruitment platforms: Builder → Basic information → 招募平台 (Prolific, CloudResearch Connect, or another platform such as Credamo). Participants who arrive with a platform ID are sent back 3 s after their answers are saved (Prolific completion code shown as a fallback), get the quota-full code when places are full, and can submit once per project (checked on load and enforced by `supabase/recruitment.sql`). Share → 招募平台 gives step-by-step instructions, the link to paste with Prolific placeholders, and one link per country or group. Wide CSV adds `recruit_platform`, `recruit_id`, `recruit_study`, `recruit_session`; pseudonymised dataset packages drop them.
- Results: "生成分析" for a custom question (an SP-Scheme page's own task that mixes several answer types in one record, e.g. two ratings, two reason lists and an A/B choice per round) now works in two steps. The Assistant model reads the question, the page code and every stored field and writes an analysis plan: what each field means in the survey's own words, which image it belongs to and how to analyse it (score, choice between images, option, tags, group, duration, text, skip, or custom code). The platform checks that the plan covers every field (missing ones are sent back once), then computes the results from the plan with its own algorithms, so the same records and plan always give the same numbers: per-image scores or an image × item table, TrueSkill ranking of the chosen images with option counts and a choice-vs-rating consistency check, tag counts with the mean score of the image each tag described, durations in seconds (cumulative timing flagged), free text, and one background table of participant attributes (age, gender, grade, AB order: counts or mean, each listed once even when the page stored it twice); a split by group only for attributes the researcher's notes ask to compare by. Scores stored once per item field (scenes[].ratings.A1, .M1, …) form one image × item table; a second copy of the same scores is counted once; JSON saved as text is read through, never analysed as free text. The plan is shown first as a 字段 → 含义 → 分析 table with skipped fields behind a toggle; charts and tables are titled by the plan's meanings. Model code is only asked for fields the plan marks as custom. Plan and code are saved together (`version: 2`); earlier code-only analyses still run. No SQL.
- SP-Scheme pages that draw their own images (`SPSite.getMedia('folder')` or an empty image list) now fall back to the platform preview media library when the project library is empty, on the live link and in Builder preview, as native questions already did (never for a published, release-managed version). Responses record `sp_site.preview_media_library`. The admin diagnosis says so and also counts questions whose images the platform draws per question.
- Admin 项目概览: projects that run an uploaded page are tagged (SP-Scheme page / imported as is / SP-Scheme questions, plus "draft not published"), with a filter and a diagnosis dialog (what participants are served, where the page's images come from, whether answers are recorded, latest responses). A download button rebuilds the upload as a ZIP: served `index.html`, embedded data files, the media the page can draw, settings, sample responses and a README with the checks.
- Citable dataset package export (README, LICENSE, CITATION.cff, datapackage.json, stimuli manifest; identifiers stripped by default).
- Journal-style figures (SVG/PNG) per question and an "All figures" ZIP.
- Silicon-vs-human agreement report on Results and in the analysis pack, with a linear calibration of silicon scores onto the human scale (slope, intercept, R², leave-one-out error; `silicon_calibration.csv`).
- Citation loop: **Cite** button, `references.bib` + `CITATION.cff` in every export, SP-Report v1 checklist, `/publications` page.
- SP-Bench human-agreement track: publish image questions as public tasks, score model predictions in the browser, submit by pull request.
- Python SDK `spsurvey` (`sdk/python`) wrapping the MCP tools; read-only MCP tools for silicon runs; `dataset_package` export format.
- Phone-preview QR code in Builder; optional "Made with SP-Survey" footer on participant pages.
- Forgot-password and resend-confirmation on the login page; 404 page.
- Image-version contrasts for counterfactual designs: when files are named `scene__version.jpg` or versions sit in folders, Results shows each version's mean per-scene difference from a baseline (95% CI, paired t, Holm-adjusted p, Cohen's d_z); the analysis pack adds `variant_contrasts.csv` and `variant_pairs.csv`.
- Qualtrics import: the project sidebar's import button accepts a `.qsf` file and creates a project (multiple choice, matrix, slider, text entry, rank order, constant sum, descriptive text); a report lists what was not converted (display logic, randomizers, unsupported types).
- Methods drafts in journal house style (Environment and Planning B, CEUS, Landscape and Urban Planning): **Cite → Methods for a journal** on Results, and `methods_for_journals/*.md` in the analysis pack. Fixed templates, no model; placeholders for recruitment and ethics.
- SP-Forum at `/forum`: categories, search, open/closed threads, replies, edit and delete own posts; authors close and reopen their threads; admins pin, hide and post announcements. Posts show a display name, never the e-mail; outside images are shown as links.
- Governance: CONTRIBUTING, RELEASING, architecture decision records, template contribution guide, issue and PR templates.

### Changed results
- Quality flag `too_fast` now also marks a submission that took under 1 second per answer (one answer per question, one per trial), whatever the other submissions did. Before, it only compared with the median, so a batch of bot submissions that were all equally fast was never flagged. MCP exports now use the same quality flags as the Results page.
- Answers given on the platform preview images (the project media library was empty) are saved as practice (`practice_mode: true`, `practice_reason: preview_media_library`), so Results and every export leave them out by default.
- Random draws: every place that shuffled images, sets or folders used `sort(() => 0.5 - Math.random())`, which is not a fair shuffle (with 10 images and 2 drawn, the first image in the library came up about 33% of the time and the last about 12%, instead of 20% each). All of them now use a Fisher–Yates shuffle, so every image has the same chance. Past responses are not changed; exposure counts in data collected before this fix can be uneven for that reason.
- Sampling modes "Adaptive", `uncertain` and `high_sigma` never did anything different from random (the statistics they relied on were never written). They now mean Balanced, and "Adaptive" is no longer offered in the question editor. Methods text says images were shown equally often only when every response of the project took its number from the platform.
- Custom-question exports gain `questions/{name}__ai__{n}_platform_{type}.csv` files computed by the platform (including `_coverage`), with or without a saved model analysis; a saved model analysis whose blocks repeat the platform's data is no longer shown or exported twice.

### SQL to run
- `supabase/balanced_draws.sql` (Balanced sampling mode). Until it is run, balanced questions draw at random, as they always did.
- `supabase/forum.sql` (SP-Forum). Until it is run, `/forum` says the forum is not switched on yet.
